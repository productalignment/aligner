# Personas

## PE-001 Solo founder-PM
- who: A founder or PM who builds the product with AI coding agents such as Claude Code
- wants: The agent to build what they mean, end to end, without writing tickets or living in raw markdown
- pains: Intent in loose prompts drifts from what gets built; specs and screenshots go stale; the agent has no stable picture of the product to work from
- context: Works in Claude Code sessions, moving between thinking about the product, sketching it, and checking what was built

### Jobs
- JB-001: When I start a product, I want to write down who it's for and the jobs they hire it for, so every change is anchored to them
- JB-002: When I plan a feature, I want to sketch its flow and mockups, or have the agent draft them, and refine them, so any model, even a cheaper one, builds exactly that
- JB-003: When a screen should change, I want to draw the change on its screenshot, so the agent builds exactly what I mean
- JB-004: When I keep prompting my coding agent to refine, refactor or fix, I want it to keep the product context current, so I can review the product at any time without losing control
- JB-005: When I look over the product, I want to see each job with the flows that serve it, so I can spot what's missing or not needed
- JB-006: When I've built a lot by prompting alone, I want the agent to map what's built and point out what doesn't fit, so I can take back control
- JB-007: When the direction changes, I want to change the vision, personas or jobs and have the agent update the flows and screens to match, so I can pivot before any code changes
- JB-008: When I'm not sure which way to go, I want to spec each option in its own branch, so I can keep the one that works
- JB-009: When I work with my tools to build a product, I want to have the most recent version, so I can benefit from latest features and work efficiently
- JB-010: When I look over the product, I want to see where every button, link and tab takes the user, so I can spot dead ends and screens nobody reaches
